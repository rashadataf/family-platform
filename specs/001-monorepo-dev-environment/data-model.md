# Phase 1 Data Model: Monorepo Scaffolding & Local Development Environment

This feature introduces no product or personal data (see [spec.md](spec.md)'s "Data Handling and Compliance" section). The entities below are the technical realization of the spec's own "Key Entities" — structural/configuration concerns, not domain data.

## Local Environment Configuration

**What it represents**: The set of environment variables an instance of the API needs to start.

**Where it lives**: Defined once as a Zod schema, `apps/api/src/config/env.schema.ts` — the single source of truth for what a valid local configuration looks like. Represented in the repository by a single root-level `.env.example` (committed, placeholder values) and, locally only, a single root-level `.env` (git-ignored, real values).

**Fields** (names final; exact defaults/constraints are an implementation detail of `env.schema.ts`, not re-specified here to avoid duplicating the schema):

| Field | Purpose |
|---|---|
| `NODE_ENV` | Runtime mode; constrained to a known set of values |
| `PORT` | Port the API listens on |
| `LOG_LEVEL` | Logging verbosity |
| `POSTGRES_PORT` | Host port the Postgres container publishes |
| `POSTGRES_DB` | Database name used by both Docker Compose and `DATABASE_URL` |
| `DATABASE_URL` | Full Postgres connection string used by Prisma and the API |

**Validation rule**: Every field MUST be present and pass its schema check before the API process proceeds past its first line of `main.ts` (Constitution Principle II; FR-008). `scripts/verify-env-example.ts` additionally asserts every key in this schema also appears as a key in `.env.example`, catching drift between the two.

**Lifecycle**: Read once, at process start. Not mutated at runtime. Holds no product or personal data.

## Migration History

**What it represents**: The ordered record of schema changes applied to a given local database instance, used to determine which committed migrations still need to run.

**Where it lives**: Prisma's own `_prisma_migrations` bookkeeping table, created and maintained automatically by `prisma migrate deploy`. Not modeled or queried directly by application code in this feature.

**Fields**: Owned entirely by Prisma's migration engine (migration id, checksum, applied timestamp, name). No custom fields are added.

**Lifecycle**: One row per applied migration file. Reset (FR-011) destroys and recreates this table along with everything else when the database is torn down and reprovisioned.

## ScaffoldProbe

**What it represents**: The single baseline migration's structural payload (FR-005) — proof that the migration mechanism can build schema from nothing, deliberately holding no product or personal data.

**Where it lives**: `packages/persistence/prisma/schema.prisma`, mapped to the table `_scaffold_probe`.

**Fields**:

| Field | Type | Purpose |
|---|---|---|
| `id` | UUID, primary key | Row identity, generated by the database |
| `createdAt` | timestamptz, defaults to now | When the probe row's schema was created; not used for any business logic |

**Validation rule**: None beyond standard column types — this table carries no business invariants.

**Lifecycle**: Created by the baseline migration. Queried (existence check only, not row content) by `packages/persistence`'s exported `checkDatabaseHealth()` function, which backs the API's `GET /health/ready` endpoint (see [contracts/health-endpoint.md](contracts/health-endpoint.md)). Explicitly temporary: a comment in `schema.prisma` marks it for deletion once the first real domain migration lands in a later feature. Not exposed outside `packages/persistence` — `apps/api` never queries it directly or sees its shape.

## Explicitly out of scope

No `Family`, `FamilyMember`, `User`, or any other product-domain entity is introduced by this feature. `ARCHITECTURE.md` §10's data architecture principles (UUIDv7 keys, `family_id` on every family-scoped table, soft delete, row-level security) apply once real domain schema is added in a later feature — none of them are relevant to `ScaffoldProbe`, which is not a family-scoped or domain table.
